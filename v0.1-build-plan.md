# Lethe v0.1 Build Plan

## Goal

Build the closed-world localhost proof in `SPEC.md`. Deliver delete end to end first, then correction, expiry, permission changes, dashboard, deterministic demo, and acceptance suite.

Lethe remains an internal codename. This build does not claim universal deletion, semantic erasure, production identity security, or coverage outside declared demo-owned stores.

## Locked stack

- Python 3.12 managed by `uv`.
- FastAPI, Pydantic, Chroma, `cryptography`, RFC 8785 canonical JSON, and standard-library SQLite in WAL mode.
- Python module `lethe_control`.
- One Python process runs API and durable worker loop.
- React, Vite, TypeScript, pnpm, native CSS/SVG, Vitest, Testing Library, and Chromium-only Playwright.
- Runtime data lives under ignored `.lethe/` paths.
- No ORM, broker, hosted SaaS, real LLM, Docker, Qdrant, or cloud connector.
- No Git initialization or commits.

## Pipeline

1. Scaffold Python package, dashboard, migrations, fixtures, scripts, lockfiles, README, Make targets, and loopback configuration.
2. Implement strict contracts, composite scope keys, SQLite transactions, lineage constraints, injected clock, deterministic IDs, and reason-coded failures.
3. Implement deterministic ingestion, chunking, feature-hash embedding, summaries, memories, caches, immutable lineage, and frozen fixture manifest.
4. Implement authoritative pre-retrieval and pre-release gate with deny-wins, policy freshness, supersession, conjunctive parent ACLs, and earliest expiry.
5. Implement authenticated/idempotent delete event, atomic deny fence plus outbox, five derivative adapters plus source handling, restart reconciliation, and payload-free tombstones.
6. Implement tracked/exact/semantic scanning, declared-scope denominators, connector read-back, bounded probes, Ed25519 receipts, SHA-256 chain, and online/offline verification.
7. Implement correction branches, clock-driven expiry cleanup, and permission narrowing/widening rules.
8. Implement React dashboard using generated OpenAPI TypeScript types.
9. Package one-command eight-stage killer demo plus separate event demos.
10. Run final unit, integration, frontend, contract, end-to-end, acceptance, restart, security, and benchmark checks.

## Runtime interfaces

- `POST /api/v1/events`
- `GET /api/v1/runs/{run_id}`
- `GET /api/v1/graph/{version_id}`
- `POST /api/v1/query`
- `POST /api/v1/demo/unsafe-query`
- `POST /api/v1/scans`
- `GET /api/v1/receipts/{run_id}`
- `POST /api/v1/receipts/verify`
- Internal `/healthz` and `/readyz`

FastAPI OpenAPI is the interface source of truth. Event bodies remain `LifecycleEvent`; fixture issuer signature travels in `X-Lethe-Event-Signature`. Query bearer token resolves alice or bob server-side.

Store adapters expose `inventory`, `apply_action`, `read_back`, and `capabilities`. Semantic matches remain report-only.

## Acceptance

- Complete four-event by five-derivative matrix. Every cell checks immediate gate behavior, physical action, read-back, lineage/tombstone state, and receipt evidence.
- Cover partial connector failure, duplicate and out-of-order events, restart persistence, stale re-ingestion, ACL narrowing, receipt tampering, chain removal/reordering, source-only deletion control, cross-scope collisions, unauthorized issuers, expired commands, permission widening, clock rollback, missing lineage, stale policy, and crash reconciliation.
- Mandatory: zero prohibited disclosures in fixed 100-query suite; unrelated-query false blocking at most 1%; unaffected access remains correct; recovery is idempotent; all tampered receipt fixtures fail.
- Reported hypotheses: scanner recall at least 95%, precision at least 90%, gate p95 overhead at most 20 ms, and 10,000-derivative propagation under 60 seconds on declared reference hardware.
- Local proof targets L3 with additional local resilience probes. It never claims L4 without an externally retained trusted checkpoint.

## Commands

- `make bootstrap`: install locked backend and dashboard dependencies.
- `make dev`: start API/worker and dashboard on loopback.
- `make demo`: reset state and execute deterministic eight-stage demo.
- `make verify`: run functional checks.
- `make benchmark`: measure and report engineering hypotheses.
